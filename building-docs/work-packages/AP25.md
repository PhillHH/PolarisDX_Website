# 10. PT25.2 — Rendering, SSR und Hydration

## Ziel

Die kritischen Renderpfade so optimieren, dass SSR schnell antwortet, Hydration keine unnötige Main-Thread-Last erzeugt und schwere Seiten nur den Code laden, den sie benötigen.

## Scope

1. SSR TTFB
2. Server render cost
3. Hydration cost
4. Long Tasks
5. route-level lazy chunks
6. heavy module splitting
7. Suspense behavior
8. client-only Widgets
9. initial route waterfalls
10. Musterbefund-/Epigenetics-heavy modules

## Leitlinien

### SSR

Messen:

- Server processing time
- TTFB lokal isoliert
- TTFB Preview
- Cold vs warm, soweit relevant
- SSR output size

Keine nginx-/Infra-Ursache als React-Fix kaschieren.

### Hydration

Messen:

- Zeitpunkt Hydration Start/Ende, soweit technisch sinnvoll
- Long Tasks
- initiale Event-Handler-/Widget-Kosten
- unnötige client-only work

Hydration muss funktional identisch bleiben.

### Route Splitting

Ziel:

- schwere Inhalte nicht im globalen Initial-Bundle
- Page-/Feature-Chunks nachvollziehbar
- keine unnötigen statischen Imports aus seltenen Routen

Besonders prüfen:

- Musterbefund-Daten
- Epigenetics
- Consumer-Media/-Widgets
- Resource Center
- Article/Event Daten

### Musterbefund

Aktuellen Zustand von `src/content/befunde/**` messen.

Falls weiterhin breite Imports existieren:

- route-/panelgerechte Teilung
- keine 322-KB-artige globale Datenlast nur wegen eines einzelnen Befundpfads
- `LanguageFallbackNotice`, Panel-Namen, Back-to-top und AP16-Verträge erhalten

### Suspense

Kein neuer Spinner-Waterfall ohne messbaren Gewinn.

SSR Content darf nicht unnötig durch Client-Fallback ersetzt werden.

### Client-only Widgets

Nur minimieren, wenn:

- tatsächlicher initialer Cost gemessen
- SSR/SEO nicht verschlechtert
- Interaktion erhalten

## Akzeptanz

- TTFB nicht regressiert
- initial render cost messbar verbessert oder bereits innerhalb Budget nachgewiesen
- schwere Route-Module aus unnötigem Initialpfad entfernt
- Hydration-Regression = 0
- 404/SEO/SSR unverändert korrekt
- no-consent Network-Gate unverändert
- A11y-Regressions = 0 im berührten Scope

# 16. Risikoregister

## R25-01 — Lighthouse-Score-Gaming

**Risiko:** Inhalt/Interaktion wird entfernt oder verzögert, um Scores zu verbessern.  
**Mitigation:** fachliche Funktion + Core Interaction Smoke + Vorher/Nachher-Evidence.

## R25-02 — Lab wird als Field ausgegeben

**Risiko:** künstlich gute Lab-Werte werden als reale Nutzerdaten interpretiert.  
**Mitigation:** harte Lab/Field-Klassifikation.

## R25-03 — Chunking erzeugt Waterfalls

**Risiko:** kleineres Initial-Bundle, aber schlechtere reale Navigation/LCP.  
**Mitigation:** Network Waterfall + Route Navigation nachmessen.

## R25-04 — Hero lazy geladen

**Risiko:** LCP verschlechtert sich durch falsche Lazy-Strategie.  
**Mitigation:** gemessene LCP-Kandidaten + Priority Guard.

## R25-05 — Überdimensionierte Bilder

**Risiko:** Mobile lädt Desktop-Assets.  
**Mitigation:** `srcset`/`sizes` + Byte-/Dimension-Checks.

## R25-06 — Bildoptimierung verschlechtert Qualität

**Risiko:** medizinische/diagnostische Visuals werden unlesbar.  
**Mitigation:** Visual QA + route-spezifische Qualitätsanforderung.

## R25-07 — Font Swap erzeugt CLS

**Risiko:** Font-Optimierung verbessert Load, verschlechtert Layoutstabilität.  
**Mitigation:** CLS-Vorher/Nachher + Fallback-Metriken.

## R25-08 — Async CSS erzeugt FOUC

**Risiko:** visueller Flash oder fehlender Focus Style.  
**Mitigation:** first-paint/keyboard regression tests.

## R25-09 — Performance Telemetry umgeht Consent/Privacy

**Risiko:** technisches Monitoring wird heimlich Marketing-Tracking.  
**Mitigation:** AP23 Separation Contract + no PII + kein GTM/GA4 Transport.

## R25-10 — Preview pollutes Production

**Risiko:** Messläufe verfälschen Production Analytics/Metrics.  
**Mitigation:** Preview Isolation + synthetische/local measurement.

## R25-11 — Budgets werden nachträglich weichgestellt

**Risiko:** rote Gates werden durch Budgeterhöhung "behoben".  
**Mitigation:** Budgetänderung braucht neue Evidence + dokumentierte Begründung.

## R25-12 — CI wird flaky

**Risiko:** Netzwerk-/CPU-Streuung blockiert Releases ohne echte Regression.  
**Mitigation:** deterministische Artefaktbudgets + kontrollierte Lighthouse-Toleranz + Wiederholungsstrategie.
