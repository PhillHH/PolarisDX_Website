# 0. Zweck und Rolle von AP19

AP19 schließt den in `DEC-RL-014` gelockten Secondary-Conversion-Pfad:

> Zusätzlich zur direkten Anfrage gibt es mindestens einen gegated Lead-Magnet-/Secondary-Conversion-Pfad.

1. **Resource Center**
   - reale Ressourcen
   - echte Sprach-/Versions-/Dateiwahrheit
   - Free-vs-Gated sichtbar und konsistent

2. **Lead-Magnet Delivery**
   - wiederverwendbares Gate
   - persistenter `content_download`-Journey-State
   - CRM-/Delivery-Handoff
   - Retry/Idempotency
   - geschützte Auslieferung
   - x10 Success-/Error-/Mail-Copy
   - Consent-getrenntes Tracking

AP19 ist erst fertig, wenn **mindestens ein realer gated Lead-Magnet-Pfad vollständig produktiv funktioniert**.

Ein Formular vor einer weiterhin frei erratbaren PDF-URL erfüllt AP19 ausdrücklich nicht.

# 21. Protected Delivery Contract

Ein gegatetes Asset darf nicht einfach als öffentlicher, erratbarer Pfad bestehen, der Gate umgeht.

- privater Storage + signierter Link
- Server-Download-Endpoint mit Entitlement-Validation
- tokenisierter Asset Resolver

`/api/download?file=../../secret`

Request akzeptiert:
stabile Asset-ID / Entitlement Token.

Server löst auf Allowlist/Registry auf.

# 33. AP19 Invarianten

## RES-01 — Predecessor Integrity

AP18 muss COMPLETE / Closure PASS sein, bevor AP19 produktiv startet.

## RES-02 — Ten Locales

Resource Center, Gate-, Success-, Error- und Delivery-Copy unterstützen exakt zehn Projektsprachen: de, en, pl, fr, it, es, pt, da, nl, cs.

## RES-03 — Default Locale

Default Locale und x-default bleiben de.

## RES-04 — Asset Inventory Truth

Alle launchrelevanten Ressourcen werden aus realem Repository-/Storage-Bestand inventarisiert; keine Phantom-Assets.

## RES-05 — Asset Stable Identity

Jede launchrelevante Ressource besitzt eine stabile Asset-ID unabhängig vom sichtbaren Dateinamen.

## RES-06 — Asset Language Truth

Jedes Asset ist genau den tatsächlich vorhandenen Sprachen zugeordnet; Web-x10 bedeutet nicht automatisch Asset-x10.

## RES-07 — No Wrong-language Fallback

Eine Locale darf niemals still auf ein inhaltlich falsches Asset einer anderen Sprache fallen.

## RES-08 — Version Truth

Version/Revision/Datum werden nur aus realer Asset-Wahrheit ausgegeben.

# 34. Risikoregister

## R19-01 — Gated PDF liegt weiterhin frei unter erratbarer `/downloads/`-URL

**Risiko:** Gated PDF liegt weiterhin frei unter erratbarer `/downloads/`-URL.

**Mitigation:** geschützte Delivery außerhalb frei erratbarer Public-URL oder serverseitig kontrollierter Asset-Zugriff.

## R19-02 — x10 Resource Center verlinkt falsche Sprachdateien

**Risiko:** x10 Resource Center verlinkt falsche Sprachdateien.

**Mitigation:** Asset-Language-Matrix + Hard Gate gegen cross-language silent fallback.

## R19-03 — Formular ist nur UI-Gate ohne Persistenz

**Risiko:** Formular ist nur UI-Gate ohne Persistenz.

**Mitigation:** Persist-before-handoff + DB-/state evidence als PASS-Voraussetzung.

## R19-04 — Providerfehler verliert Leads/Zustellungen

**Risiko:** Providerfehler verliert Leads/Zustellungen.

**Mitigation:** Retryfähiger persistenter Status + idempotenter Replay.

## R19-05 — Token-/Download-Link ist global oder dauerhaft offen

**Risiko:** Token-/Download-Link ist global oder dauerhaft offen.

**Mitigation:** Asset-/Lead-gebundene Entitlements + Expiry/Validation, wenn tokenisiert.

## R19-06 — Path Traversal/Arbitrary File Download

**Risiko:** Path Traversal/Arbitrary File Download.

**Mitigation:** nur stabile Asset-ID akzeptieren; serverseitige Allowlist/Registry, niemals User-Pfad direkt lesen.

## R19-07 — Doppel-Submit erzeugt mehrere CRM-Leads oder Mails

**Risiko:** Doppel-Submit erzeugt mehrere CRM-Leads oder Mails.

**Mitigation:** Idempotency Key / uniqueness + delivery dedupe.

## R19-08 — Marketing-Consent wird zur Voraussetzung für notwendigen Download

**Risiko:** Marketing-Consent wird zur Voraussetzung für notwendigen Download.

**Mitigation:** Consent Separation; Business-Delivery unabhängig von Analytics/Marketing.

## R19-09 — Tracking sendet pre-consent

**Risiko:** Tracking sendet pre-consent.

**Mitigation:** provider-agnostische Fassade + Network-Gate.

## R19-10 — Resource Center zeigt alte/verwaiste Dokumente

**Risiko:** Resource Center zeigt alte/verwaiste Dokumente.

**Mitigation:** Launch Visibility Status + Version/Date/Owner-Evidenz.

## R19-11 — AP19 baut eine parallele Lead-Plattform neben AP22

**Risiko:** AP19 baut eine parallele Lead-Plattform neben AP22.

**Mitigation:** nur wiederverwendbarer `content_download` Vertical Slice; Cross-Journey-Standardisierung bleibt AP22.

## R19-12 — Success behauptet Download/Mail obwohl Delivery scheitert

**Risiko:** Success behauptet Download/Mail obwohl Delivery scheitert.

**Mitigation:** State-basierte Success/Error/Recovery UX und echte Delivery Evidence.

# 40. Abschluss

PolarisDX besitzt ein echtes zehnsprachiges Resource Center mit belastbarer Asset-, Sprach-, Versions- und Free/Gated-Wahrheit.
