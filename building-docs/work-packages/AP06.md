# 0. Zweck und Rolle von AP06

AP06 baut die globale Relaunch-Shell auf dem in AP05 konsolidierten Sales-Machine-Light-Design-System auf.

Das Arbeitspaket macht die globale Navigation:

- konsistent;
- zehnsprachig;
- tastaturbedienbar;
- mobil nutzbar;
- route-sicher;
- frei von Chat-/HiHuman-Frontend-Abhängigkeiten;
- frei vom alten Garantie-/Performance-CTA-Band;
- Epigenetik-seitig korrekt.

Die zentrale Zielaussage lautet:

> Die PolarisDX-App-Shell funktioniert in allen zehn Sprachen, zeigt Epigenetik als eigenständige Hauptsäule, verwendet für den allgemeinen Sales-Weg konsistent „Angebot anfragen“, lädt keinen Chat-/HiHuman-Frontend-Rest und bringt das alte Garantie-Band nicht zurück.

AP06 besitzt die **globale Shell**. Es besitzt ausdrücklich nicht die komplette Suchfunktion, die zentrale Route Registry, Consent-Semantik, Lead-Persistenz oder umfassende Accessibility-Härtung.

- `ChatWidget`-Rendering;
- HiHuman-Frontend-Loader;
- Chat-Trigger;
- Chat-Navigation;
- Chat-CTA;
- Chat-bezogene Shell-Abhängigkeiten.

- `/api/chat` Backend vollständig entfernen → AP22 PT22.7;

## 3.4 Kein Garantie-Band

- `CtaSection`/`CtaBand` mit Garantieversprechen;
- „garantierte Performance“ als globaler CTA-Band-Claim.

Eine fachlich legitime Verwendung einer Formulierung innerhalb normalen Service-Fließtexts darf nicht blind durch String-Suche entfernt werden. Gate auf CTA-/Komponenten-/Locale-Rolle begrenzen.
