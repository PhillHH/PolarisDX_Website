## 4. HTTPS-, Proxy- und Origin-Modell

```text
Client ──TLS──▶ Host-nginx (443, Certbot) ──http──▶ SSR server.ts (127.0.0.1:2026 Prod / :9100 Preview)
                  │ 80 → 301 https://$host$request_uri          └─/api (http-proxy-middleware, xfwd=false)──▶ Backend server.js
                  │ X-Forwarded-For: $proxy_add_x_forwarded_for                                             (127.0.0.1:5000 Prod / :5100 Preview)
                  │ X-Forwarded-Proto: $scheme, Host: $host                                                  trust proxy = 1
```

| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| TLS-Terminierung, HTTP → HTTPS | Host-nginx, beide Origins (`http://…` → 301 `https://…`)                                                                                                                    | korrekt; **nicht** repository-owned                                                                                    |
| HSTS                           | Produktion **fehlt**, Preview **fehlt** (DD-14 bestaetigt); nur die Alt-Site `relaunch.polarisdx.net` sendet HSTS (mit `includeSubDomains`, gilt nur fuer deren Subdomains) | Konfiguration jetzt im Repo (§4.1); Live = OA-1                                                                        |
| Forwarded-For                  | nginx **haengt an**; SSR reicht unveraendert durch (`xfwd` aus); Backend `trust proxy 1` nimmt den **letzten** Eintrag = echte Client-IP                                    | Faelschung wirkungslos hinter dem Proxy — E2E Test 3: 4 gefaelschte Adressen, Limiter greift beim 6. Aufruf            |

### 4.1 HSTS-Konfiguration

- Datei `deploy/nginx/polarisdx-hsts.conf`: `add_header Strict-Transport-Security "max-age=31536000" always;`
- **ohne `includeSubDomains`** (nicht jede Subdomain ist als reiner HTTPS-Dienst belegt), **ohne `preload`** (eigene Operator-Entscheidung, praktisch nicht rueckholbar).
- nur im 443-Block von `polarisdx.net`/`www.polarisdx.net`; wegen nginx-Vererbung in Locations mit eigenem `add_header` (produktiv die `/early`-Locations) erneut einbinden.
- Produktionsnaher Nachweis: E2E Test 1–4 — HSTS genau einmal auf HTML 200/301/404, Assets, Locales, API 2xx/4xx/413/429, geschuetzt 200/403; nicht auf HTTP; nicht am SSR direkt.
- **Status: produktionsreif (PASS im Repo), Live-Aktivierung AP31 Operator-Check (OA-1)** — gestaffelt: erst `max-age=86400`, pruefen, dann Zielwert.

## 6. API-Endpoint-Matrix (Stand PT26.3, gemessen)

Alle Pfade laufen oeffentlich ueber `https://<origin>/api/*` → SSR-Proxy → Backend (`127.0.0.1`, SEC-15). Gemeinsam fuer jede schreibende Route (Reihenfolge): Baseline-Header → Fetch-Metadata-Guard (403 `CROSS_SITE_REQUEST`) → `formLimiter` 5 / 15 min je IP (**geteilt**) → JSON-Pflicht (415) → Parser mit Routengrenze (413) → nur JSON-Objekt (400 `INVALID_JSON`) → Key-Format (400 `IDEMPOTENCY_KEY_INVALID`) → Journey-Service (Key-Pflicht, Honeypot, Schema, Consent, Persistenz vor Provider) → Envelope. CORS: nur fuer konfigurierte `FRONTEND_URL`. Unbekannte Felder werden angenommen, aber **weder gespeichert noch gespiegelt** (Services bauen Subject/Kontext aus benannten Feldern; Test mit `isAdmin`, `recipient`, `leadId`, `constructor.prototype`).

## 8. CSP — Stand nach PT26.2

### 8.1 Vorher (PT26.1-Eingang)

`Content-Security-Policy-Report-Only` ohne Empfaenger; `script-src 'self' 'unsafe-inline' 'unsafe-eval'` + GTM/GA + `https:`; Schema-Quelle `https:` in sechs Direktiven; veraltete Origins `ssl.google-analytics.com`, `fonts.googleapis.com`, `fonts.gstatic.com`; `style-src 'unsafe-inline'`; nichts durchgesetzt.

### 8.2 Nachher — Zielpolicy, in Produktion durchgesetzt

Einzige Quelle: `src/security/contentSecurityPolicy.ts` (`buildContentSecurityPolicy`, `resolveCspMode`); `server.ts` setzt nur den Header.

```text
default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'self'; form-action 'self';
script-src 'self' https://www.googletagmanager.com;
style-src 'self' 'sha256-<inline App-CSS>'; style-src-elem 'self' 'sha256-<inline App-CSS>'; style-src-attr 'unsafe-inline';
connect-src 'self' https://region1.google-analytics.com; img-src 'self' data:; font-src 'self'; frame-src 'none'
```

| Punkt                   | Stand                                                                                                                                                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Modus                   | `NODE_ENV=production` → **`Content-Security-Policy`** (durchgesetzt). Entwicklung → Report-Only (Vite spritzt Inline-Skripte/Styles ein). `POLARIS_CSP_MODE=report-only` = Rueckfallschalter; unbekannter Wert → `enforce` |
| Geltungsbereich         | SSR 200/404 (mit Hash), Redirects, API-Proxy- und Fehlerantworten (ohne Hash); statische Dateien weiterhin ohne CSP (unveraendert §3.1)                                                                                    |
| Hash                    | SHA-256 des inline ausgelieferten App-Stylesheets (PT25.4), beim Einlesen berechnet; E2E vergleicht Header-Hash mit dem ausgelieferten `<style>`-Inhalt                                                                    |
